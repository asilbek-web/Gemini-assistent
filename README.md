# Telegram Business Assistant Bot

A personal assistant bot for a Telegram Business account. When someone
messages you, the bot drafts a reply **in your name, in your style**, using
your profile (`profile.md`).

Two engines, pick either — no Anthropic API key is ever used:

- **Gemini (free)**: set `GEMINI_API_KEY` (from
  aistudio.google.com/apikey, no card needed) and the bot uses the free
  Gemini API. No subscription required.
- **Claude CLI (subscription)**: leave the Gemini key empty and set
  `CLAUDE_CODE_OAUTH_TOKEN` (from `claude setup-token`); replies are
  generated by your Claude Code subscription.

`GEMINI_API_KEY` wins when both are set.

**Preview mode is the default.** Replies are only printed to the logs
(`PREVIEW, not sent`) until you set `AUTO_SEND=true`. Which chats the bot
sees is decided entirely by Telegram itself: Settings → Telegram Business →
Chatbots. There is no allowlist in the code.

## Behaviour

| Situation | What happens |
| --- | --- |
| Message from a foreign business connection | Ignored (no Claude call) |
| Which chats are visible | Telegram decides (Business → Chatbots) |
| You write in a chat | Your message is logged; the bot stays quiet for `OWNER_TAKEOVER_MINUTES` |
| Another bot's message | Ignored |
| Duplicate update (redelivery, restart) | Processed once |
| Service messages (no text/caption/sticker) | Ignored |
| `/pause` (owner only) | Stops replying; state survives restarts |
| `/resume`, `/status` (owner only) | Resume / show mode, state, limit, chat count |
| Subscription usage limit | Cooldown until reset; owner is notified in auto-send mode |
| Timeout or login error | Nothing is sent to the chat; owner is notified (max once per 10 min) |
| No reply needed | Claude answers `[SKIP]`; nothing is shown or sent |
| Auto-send permission removed mid-generation | Reply is withheld and logged as a preview with a reason |

Owner commands (`/pause`, `/resume`, `/status`) and `/start` work only in a
private chat with the owner and are answered in Uzbek. `/start` explains how
to connect the bot through Telegram Business → Chatbots. Strangers who
message the bot directly get a short Uzbek note; the profile is never
revealed and Claude is never called.

## How replies are generated

With `GEMINI_API_KEY` set, each reply is one HTTPS call to
`generativelanguage.googleapis.com` with the key in a header only (never in
logs or argv). Timeouts map to the same error handling as below.

Without it, every reply is one isolated `claude -p` run:

Every reply is one isolated `claude -p` run:

- `--safe-mode --tools "" --strict-mcp-config --setting-sources ""`
  `--disable-slash-commands --no-session-persistence`
  `--system-prompt-file <tempfile> --output-format json --effort <level>`
- The message text goes over **stdin only** (never argv). The system prompt
  (profile included) is a temporary `0600` file, deleted afterwards.
- `--bare` is deliberately **not** used: it ignores the OAuth login and would
  break subscription auth.
- The child environment is scrubbed: every `ANTHROPIC_*` variable, the bot
  token, and the Claude token are removed, then
  `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` and `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`
  are set. The subscription token is injected only via
  `CLAUDE_CODE_OAUTH_TOKEN` when configured.
- Auth comes from `claude setup-token` (`sk-ant-oat...`), a one-year
  subscription token — **not** an API key. An `sk-ant-api...` value is
  rejected at startup.
- Verify everything with `python bot.py --check-claude`.

## Deploy to Railway

1. On a machine with a browser: `claude setup-token` → copy the
   `sk-ant-oat...` token.
2. @BotFather: `/newbot`, then Bot Settings → enable **Business Mode**. Get
   your numeric ID from @userinfobot.
3. Create a **private** GitHub repository (the image contains `profile.md`)
   and push this code.
4. Railway → New Project → GitHub Repository → select the repo.
5. Service → Variables → Raw Editor (free Gemini engine):

   ```
   TELEGRAM_BOT_TOKEN=<from @BotFather>
   OWNER_ID=<your numeric id>
   GEMINI_API_KEY=<from aistudio.google.com/apikey>
   AUTO_SEND=false
   ```

   Or the Claude subscription engine: replace `GEMINI_API_KEY` with
   `CLAUDE_CODE_OAUTH_TOKEN=<sk-ant-oat...>`.

   Optional: `CLAUDE_MODEL`, `CLAUDE_EFFORT`, `CLAUDE_TIMEOUT_SECONDS`,
   `LIMIT_COOLDOWN_MINUTES`, `OWNER_TAKEOVER_MINUTES`, `HISTORY_LIMIT`.
   `CLAUDE_BIN`, `DATA_DIR`, `PROFILE_PATH` are not needed on Railway.
6. Volume: on the canvas (or Cmd+K) → Volume → pick the service →
   mount path exactly `/app/data` → Deploy. Without a Volume, history,
   pause state, and limit cooldowns are lost on every deploy.
7. Logs must show: `Bot @... is running`, `Mode: PREVIEW`, `Engine: gemini`
   (or `claude`) and the matching auth line. Red text on Railway is just
   stderr, not necessarily an error.
8. Message the bot `/start`, then Telegram → Settings → Telegram Business →
   **Chatbots** (Telegram Premium required): add the bot's username, pick the
   chats it may see, and allow replies. Logs show
   `Business connection ...: user=<id> enabled=True`.
9. When someone messages you, the logs show a `PREVIEW, not sent` block.
   If the drafts look right, set `AUTO_SEND=true` and redeploy.

Notes:

- Run the bot in **one place only**: two polling loops with the same token
  fight each other (do not start local `python bot.py` while Railway runs).
- Every push redeploys; to change `profile.md` you also commit + push.
- Token leaked or expired: rerun `claude setup-token` and update the Railway
  variable. Bot token leaked: `/revoke` in @BotFather.

## Local development

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env && chmod 600 .env   # then edit it
python bot.py --check-claude             # verify auth + isolation
python bot.py --try "Salom, qalesan?"    # one test reply, no Telegram
python bot.py                            # run with long polling
```

If `CLAUDE_CODE_OAUTH_TOKEN` is empty locally, this machine's own `claude`
login is used (fine for testing).

## Commands and exit codes

| Command | Purpose |
| --- | --- |
| `python bot.py` | Run the bot from `.env` |
| `python bot.py --settings-from-env` | Run from process env (container) |
| `python bot.py --check-claude` | Print auth/isolation report as JSON |
| `python bot.py --try "text"` | Print language, message, and reply |

Exit codes: `0` success, `1` check failed (`--check-claude` / `--try`),
`2` configuration or token error.

## Tests

```bash
pip install -r requirements-dev.txt
pytest
```

All tests run offline with a fake `claude` script and a recorded Telegram
session; no account or token is needed.
